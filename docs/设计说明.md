## 2. 流水灯逻辑

### 2.1 显示原理：4×8 动态扫描 + 双维度亮度

32 颗 LED 需要独立亮度，但单片机 IO 数量有限、且题目明确要求“**不要用单片机直接驱动大量 LED**”。采用的方案是：

#### （1）动态扫描点亮

把 32 颗 LED 组织成 **4 行 × 8 列** 的矩阵：

- **行（字符）= 高边**：4 个字符各自由一颗 **PMOS（AO3401）** 控制阳极供电；
- **列（点）= 低边**：每个字符的第 *k* 个点共用同一条阴极线，一共 8 条，各由一颗 **NMOS（AO3400）** 控制；
- 任意时刻**只打开一行**（一个字符的阳极），其余三行 PMOS 关断。

于是 32 颗 LED 只需要 **4 + 8 = 12 个 IO**，而且任何时刻每条阴极线上最多只有一颗 LED 导通，**每颗点亮的 LED 都独占自己那一列的限流电阻**（这一点很关键，见 §3.4）。

#### （2）三个定时器分工

| 定时器 | 频率 | 职责 |
|---|---|---|
| **TIM1** | 1 kHz | **槽切换**：每 1ms 换一个字符，4 个字符轮一遍 = 4ms = 一帧，刷新率 **250Hz** |
| **TIM2** | 20 kHz | **阴极软件 PWM**：每个 1ms 槽内 20 个 50µs tick，做整字符的亮度调制 |
| **TIM3** | 100 Hz | 应用节拍（按键、电位器、模式推进、遥测），并同时作为 **ADC 的外部触发源** |

#### （3）两个维度的亮度控制

这是本设计最核心的显示机制：

- **第一个维度 —— 整字符亮度 `duty`（0~19 级）**
  MOS 开关只能通断，亮度靠 PWM 占空比调。阴极 PWM 做在**共用的阴极线**上，所以一个槽内该字符的 8 个点本来只能同亮度。

- **第二个维度 —— 单点亮度权重 `weight`（0~8 级）**
  为了在同一个字符内做出明暗层次（彗尾、渐亮、渐变），把每个 1ms 槽**再切成 8 个子时段**：

  ```
  权重 w 的点 = 在该槽的前 w 个子时段点亮、后 (8−w) 个熄灭
  子时段边界 k 对应的 tick 数 = duty × (k+1) / 8
  该点的实际导通时间 = ⌊duty × w / 8⌋ 个 tick
  ```

  8 个点的掩码由权重自动推导并预计算成 `g_submask[4][8]`，中断里只需一次查表和一次 GPIO 写。

**效果**：32 颗 LED 各自拥有 **19 × 8 种亮度组合**，可以做平滑彗尾、逐点渐亮、整屏呼吸，而**不需要任何额外的驱动芯片或引脚**。

#### （4）硬件不变的约束

上面这套机制全部在**已冻结的硬件**上实现：12 个 GPIO、3 个定时器、没有专用 LED 驱动、没有恒流源。所有亮度能力都来自固件对时间的切分。

### 2.2 五种流水/动态逻辑

`KEY2` 短按循环切换，切到第 *n* 个模式时**整屏快闪 n 下**作为提示（板子上没有屏幕）。

| # | 名称 | 逻辑描述 | 一轮时长（默认速度） |
|---|---|---|---|
| **MODE1** | **累计书写 + 逆序擦除** | 一条“笔尖”从 B 的第 1 点出发沿 32 个点前进：**走过的地方累积点亮**，笔尖所在的那一颗按 0→满档 **渐亮**（约 120ms）。32 点全亮后保持 0.3s；然后笔尖回到起点**按同样顺序再扫一遍，被扫过的点渐灭**；全灭保持 0.2s 后循环 | 8.18s |
| **MODE2** | **字符流水** | `B → N → G → U` 依次**整字符点亮**，每个字母保持一段时间后熄灭，再亮下一个，循环 | 0.36s/字母，一轮 1.44s |
| **MODE3** | **同步呼吸** | 32 颗点权重全满，四个字母的**整体亮度同步**做 `0 → 峰值 → 0` 的呼吸（半正弦包络），最高点和最低点各停一小段（“吸-停-呼-停”） | 4.2s |
| **MODE4** | **流水 + 呼吸** | **只有当前字母的 8 个点亮着**并做一次完整呼吸（暗→亮→暗），完成后换下一个字母。**换字母发生在 duty=0 的全黑瞬间**，所以交接处看不见接缝 | 2.1s/字母，一轮 8.4s |
| **MODE5** | **描边游走（彗尾）** | 一颗“彗星”沿 32 个点游走：头部 1 点渐亮、尾部 3 点渐暗，形成柔和拖尾。**同时兼作上电自检动画** | 5.84s |

#### MODE1 的“书写”是怎么做出来的

不是“一格一格硬跳”，而是维护一个**连续位置** `pos`（单位 1/12 个点），每颗点的亮度 = **它落后笔尖多远**的线性斜坡：

```
pos ≤ 该点位置                  → 写：0（还没写到）   擦：满档（还没擦到）
pos − 该点位置 ≥ 斜坡宽度       → 写：满档（写完了）   擦：0（擦掉了）
否则                            → 写：0→满档线性上升  擦：满档→0线性下降
```

和 MODE5 彗尾用的是同一套思路，区别只在笔尖后面的点是“衰减回 0”（彗尾）还是“保持满档”（写字）。

#### 为什么擦除是“逆序”

题目示例中提到“逐个点亮并累积，全部亮后再按原顺序逐个熄灭”。这里“按原顺序”指**熄灭的推进方向与书写方向相同**（都从 B 的第 1 点往 U 的最后一点推进），视觉上是“一笔一笔写上去、再一笔一笔擦掉”，而不是从尾部倒着退回来。

### 2.3 开机流程

```
上电（按住电源键）
  ↓
MCU 初始化 → KEY1(PB11) 置高 → 保持 XL1509 的 EN 有效 → 松手后继续供电
  ↓
【自检动画】MODE5 跑一轮：固定 120ms/点、固定满档亮度
  （完全不受电位器和 KEY3 影响 —— 自检必须每次都一样，而且一定要看得见）
  ↓
全黑待机，等按键
  ↓
按 KEY2/KEY3（或蓝牙发指令）→ 进入 MODE1 开始正常演示
```

自检动画兼作**焊接/接线核对**：哪一颗灯不亮、哪一路 MOSFET 没焊好，一眼就能定位。

## 3. 元件选型依据

### 3.1 主控：STM32F103C8T6

题目限定使用 STM32F103 系列。选 **C8T6**（LQFP48）的理由：

| 需求 | C8T6 提供 | 余量 |
|---|---|---|
| IO 数量 | 37 个 GPIO | 本设计用 **22 个**（4 阳极 + 8 阴极 + 2 ADC + 2 串口 + 2 SWD + 3 按键 + 1 电源自锁） |
| 定时器 | TIM1（高级）+ TIM2/3/4 | 用 3 个，TIM4 空闲 |
| ADC | 2 路 12 位 | 用 2 路（电位器 + 电源键）刚好 |
| Flash | 64 KB | 用 33.4 KB（51%），留出扩展空间 |
| RAM | 20 KB | 用 4.5 KB（22%） |
| 主频 | 72 MHz | 扫描中断总占用约 8%，余量充足 |
| 成本/可得性 | 极常见、价格低 | 符合题目“物料成本 50 元以内” |

**注意**：题目明确“除单片机核心板外不允许使用非自制电路模块”，所以 LED 驱动部分**没有使用任何现成模块或专用驱动芯片**（如 TM1640、MAX7219），全部由分立的 PMOS/NMOS + 固件扫描实现。

### 3.2 开关管：AO3401（PMOS）+ AO3400（NMOS）

题目提醒“单片机 IO 口驱动能力有限，不要用单片机直接驱动大量 LED”。核对一下：

- STM32F103 单个 IO 绝对最大灌/拉电流 20mA，推荐连续 8mA；整片总和 ≤150mA
- 若 32 颗 LED 直接挂 IO：按每颗 12mA 算，一帧内峰值 96mA，**远超单口能力**，且总电流也接近芯片上限
- 另外高边直接由 IO 供电时，IO 输出高电平约 3.3V（实际 3.0~3.3V），压降落在 IO 内部电阻上会进一步降低亮度且发热

所以用 **MOSFET 做开关**，让 LED 电流走电源回路、不经过 IO：

| | 高边 | 低边 |
|---|---|---|
| 型号 | **AO3401（P 沟道）** | **AO3400（N 沟道）** |
| 封装 | SOT-23（贴片） | SOT-23（贴片） |
| 数量 | 4（每个字符一颗） | 8（每条阴极线一颗） |
| **必须逻辑电平** | Vgs(th) = −0.5 ~ −1.3V | Vgs(th) = 0.7 ~ 1.4V |
| Rds(on) @ Vgs=3.3V | 约 **75 mΩ** | 约 **28 mΩ** |
| Vds 耐压 | 30 V（> 3.3V，安全） | 30 V |
| 栅极电荷 Qg | 约 5.4 nC（驱动损耗极小） | 约 2.5 nC |
| 导通损耗 | 96mA² × 0.075Ω ≈ **0.7 mW** | 12mA² × 0.028Ω ≈ **0.004 mW** |

**为什么必须选“逻辑电平”管**：3.3V 栅极驱动下，普通 MOS 的 Vgs(th) 可能高达 2~4V，会出现“半开”状态 —— 既发烫又压降大。AO3401/AO3400 在 Vgs=3.3V 时已充分导通，Rds(on) 只有几十毫欧，压降可以忽略。

**PMOS 的栅极驱动方式**：源极接 3.3V，栅极由 GPIO 拉低（0V）时 Vgs = −3.3V 完全导通；拉高（3.3V）时 Vgs = 0V 关断。**因此“阳极高电平 = PMOS 关断”**，固件里关机/消隐时把 4 个阳极全部置高。

### 3.3 限流电阻计算过程（题目要求的重点）

#### 已知条件

| 量 | 取值 | 来源 |
|---|---|---|
| 供电电压 Vcc | **3.3 V** | XL1509 降压输出 |
| LED 正向压降 Vf | **2.0 ~ 2.2 V**（红光照 AlInGaP 贴片 LED 典型值，按 2.1V 计算） | LED 数据手册 |
| LED 额定连续电流 If(max) | **20 mA** | LED 数据手册 |
| PMOS 导通电阻 Rds(on) | 75 mΩ | AO3401 数据手册（Vgs=−3.3V） |
| NMOS 导通电阻 Rds(on) | 28 mΩ | AO3400 数据手册（Vgs=3.3V） |
| PCB 走线与焊点寄生电阻 | 约 30 mΩ（估算） | —— |

#### 第 1 步：确定开关回路的寄生压降

目标电流先按 12mA 估算：

```
V_switch = I × (Rds_PMOS + Rds_NMOS + R_走线)
         = 12mA × (0.075 + 0.028 + 0.030) Ω
         = 12mA × 0.133 Ω
         ≈ 1.6 mV
```

**只有 1.6mV，相对 3.3V 可以忽略**（这正是选低 Rds(on) 逻辑电平 MOS 的好处），但计算里仍然保留。

#### 第 2 步：确定目标工作电流

LED 额定 20mA 是**绝对最大值**。长期工作按额定值的 **60%** 取，取整为 **If = 12 mA**：

- 结温低、光衰慢、寿命长；
- 电流与亮度并非线性（人眼对亮度是幂律响应），12mA 与 20mA 的**视觉亮度差只有约 15%**，但发热和光衰差别明显；
- 留出 Vf 批次分散带来的电流波动余量（见第 4 步）。

#### 第 3 步：计算限流电阻

```
R = (Vcc − Vf − V_switch) / If
  = (3.30 V − 2.10 V − 0.0016 V) / 0.012 A
  = 1.1984 V / 0.012 A
  = 99.87 Ω
```

取 E24 系列标准值 → **R = 100 Ω** ✓

#### 第 4 步：校核极端情况（Vf 批次分散）

红光 LED 的 Vf 在批次间可能落在 1.9 ~ 2.3V，对应电流：

| Vf | 电流 I = (3.3 − Vf − 0.002) / 100.1 | 占额定值 |
|---|---|---|
| 1.9 V（偏亮批次） | **14.0 mA** | 70% ✅ |
| **2.1 V（典型）** | **12.0 mA** | **60%** ✅ |
| 2.3 V（偏暗批次） | **10.0 mA** | 50% ✅ |

**三者都低于 20mA 额定值**，最坏情况下仍有 30% 余量 ✅

#### 第 5 步：校核电阻功率

```
峰值功率  P_R = I²R = (0.014 A)² × 100 Ω = 19.6 mW
```

0805 封装电阻额定功率 1/8 W = **125 mW**，峰值占用仅 **16%** ✅

考虑扫描后实际平均功率更低（每颗 LED 只在 1/4 时间导通）：

```
平均功率 = 19.6 mW × (19/20 占空比) × (1/4 扫描) ≈ 4.7 mW   （占额定的 3.8%）
```

**结论：100Ω / 0805 完全安全，甚至可以再选更小封装。**

#### 第 6 步：由电阻值反推整机电流（供电源选型用）

```
单颗 LED 导通时的电流            ≈ 12 mA（峰值）
单颗 LED 平均电流 = 12 × (19/20) × (1/4)   ≈ 2.85 mA

LED 阵列峰值（同一字符 8 颗全亮） = 12 mA × 8        = 96 mA
LED 阵列平均（从 3.3V 轨取）     = 96 × 0.95 × 0.25  ≈ 22.8 mA

3.3V 轨峰值 = 96 mA（LED）+ ≈35 mA（MCU + 串口/蓝牙） ≈ 131 mA
3.3V 轨平均 ≈ 22.8 mA + 35 mA ≈ 58 mA
```

| **电源选型要求**：输出能力 ≥ 300mA（留 2 倍以上余量以覆盖 LED 阵列峰值突加）。本设计选用 **XL1509-3.3 降压型 DC-DC**，其最大开关电流 2A，**余量 15 倍以上**（详见 §3.6）。

> **注意**：LED 阵列的 96mA 是**周期性脉冲负载**（1ms 通、3ms 断，250Hz），不是恒定负载。对开关电源而言，这类负载要求输出滤波电容具备足够的**瞬态响应能力**（见 §3.6 电容选型）。

### 3.4 为什么限流电阻放在“列”（阴极）而不是“每颗 LED 一颗”

- **数量**：8 颗 0805 电阻 vs 32 颗，节省约 3 倍板面积与成本；
- **共用会不会分流失衡？** 只有多颗 LED **同时、同列、不同行**导通时才会共用一颗电阻。本设计**任意时刻只打开一行**（动态扫描），所以每条阴极线上最多只有一颗 LED 导通 —— **每颗点亮的 LED 都独占自己那一列的限流电阻**，不存在 Vf 不一致导致的分流失衡 ✅

> ⚠️ **必须说明的边界条件**：如果**关闭扫描**（把 4 个阳极同时打开），则 4 颗 LED 会经同一颗 100Ω 电阻并联，Vf 低的会抢走大部分电流（实测可达 2:1 ~ 3:1），出现“有的亮有的暗、电阻发热”。**本固件始终扫描**，所以不会进入这个状态。
>
> 另外需要澄清一个常见误解：4 颗并联时总电流**并不会**变成 4 倍 —— 电阻上的压降是共享的，总电流仍受电压预算约束（≈11.7mA 总量，而不是 4×11.7mA）。真正的问题是**分流不均**和**亮度不一致**，而不是过流烧电阻。

### 3.6 电源设计：XL1509 降压 + EN 使能开关

#### 为什么用开关电源而不是 LDO

| | LDO（线性稳压） | **XL1509（降压型 DC-DC）** |
|---|---|---|
| 输入范围 | 受压差限制，输入越高自身损耗越大 | **4.5V ~ 40V** 宽输入 |
| 效率 | ≈ Vout/Vin。5V→3.3V 只有 66%，30V→3.3V 只有 **11%** | **约 84%（5V 输入）~ 66%（30V 输入）**，与输入电压关系不大 |
| 30V 输入时的自身功耗 | (30−3.3)×0.058A ≈ **1.5W** → 需要大片散热铜皮，封装也扛不住 | 约 **288mW**（含输出功率 190mW，即自身损耗不到 100mW） |
| 静态电流 | 通常 5mA 量级，**一直消耗** | 工作静态电流 2mA；**EN 拉低进入关断态后仅几十 µA 量级** |

题目要求“电源电压拓展至 4V~30V 时仍能稳定工作”。**如果沿用 LDO，30V 输入时它自己要烧掉 1.5W，方案根本不成立** —— 这是选择开关电源的根本原因。

#### 输入范围为什么是 5V ~ 30V（而不是题目写的 4V）

- **下限 5V**：XL1509 是降压型（Buck）拓扑，**只能降压不能升压**，且数据手册给出的**最小压差为 1.5V**。要稳定输出 3.3V，输入至少需要 `3.3 + 1.5 = 4.8V`。题目要求的 4V 下限在物理上无法实现（除非改用升降压拓扑）。取 **5V** 留出 0.2V 裕量，同时对齐 USB 供电标准（USB 允许 4.75~5.25V，因此实际使用时应保证输入不低于 5V）。
- **上限 30V**：XL1509 的输入绝对最大值是 40V。取 30V 而不是顶到 40V，是为了给**输入端瞬态和振铃**留出余量（长导线接入、热插拔、感性负载反冲都可能让瞬时电压超过稳态值），同时降低高压差下芯片内部的开关损耗与温升。**这是“为了系统稳定性主动降额”的工程取舍。**

> 结果：题目要求的“宽压输入”以 **5V ~ 30V** 达成，下限比题目高 1V，原因已在上文说明。

#### 关键参数计算

**计算前提**（取自 §3.3 第 6 步的整机功耗核算）：

| 参数 | 值 | 来源 |
|---|---|---|
| 开关频率 fsw | **150 kHz**（周期 T = 6.67 µs） | XL1509 固定频率 |
| 输出电压 Vout | 3.3 V | —— |
| 输入电压 Vin | 5 V ~ 30 V | 设计范围 |
| 负载电流 Iout | 平均 **58 mA**，峰值 **131 mA**（LED 阵列 96mA + MCU/外设 35mA） | §3.3 第 6 步 |
| 续流二极管正向压降 Vf | ≈ 0.35 V（肖特基，取 0.3~0.45V 中间值） | SS34 数据手册 |

---

**① 占空比**

```
D ≈ Vout / Vin          （一阶估算，忽略二极管与开关管压降）

  Vin = 5 V  → D = 3.3/5  = 0.66
  Vin = 30 V → D = 3.3/30 = 0.11
```

> 若把二极管压降与开关管压降算进去，`D = (Vout+Vf)/(Vin+Vf−Vsw)`，5V 时约 0.72、30V 时约 0.12。两者相差不大，下文计算用一阶估算即可，结论不变。

---

**② 电感感值 47 µH 的确定**

电感纹波电流只用一条公式：

```
ΔI_L = Vout × (1 − D) / (L × fsw)
```

**最恶劣的情况出现在输入电压最高时**（D 最小 → 电感两端压差最大 → 电流上升最快）：

```
Vin = 30 V，D = 0.11
ΔI_L = 3.3 × (1 − 0.11) / (47µH × 150kHz)
     = 2.937 / 7.05
     ≈ 0.42 A        ← 最大纹波（峰峰值）
```

对比 5V 输入：

```
Vin = 5 V，D = 0.66
ΔI_L = 3.3 × (1 − 0.66) / 7.05 = 3.3 × 0.34 / 7.05 ≈ 0.16 A
```

**峰值电感电流校核**：

```
I_L,pk = Iout,peak + ΔI_L/2 = 131 mA + 210 mA ≈ 0.34 A
```

- 远低于 XL1509 的 **2A 开关电流上限**（余量约 6 倍）；
- 也低于常见 47µH 功率电感的**饱和电流**（一般 ≥0.5A）；
- 触点：**电感必须选饱和电流 ≥0.5A、直流电阻尽量小**的型号，否则大纹波下会饱和、效率下降。

**感值大小的权衡**：

| 感值 | 纹波 ΔI_L（30V 输入） | 优点 | 缺点 |
|---|---|---|---|
| 22 µH | ≈ 0.89 A | 体积小、成本低、瞬态响应快 | 纹波大 → 输出纹波大、电感和电容的 RMS 电流大 |
| **47 µH（选用）** | **≈ 0.42 A** | **纹波与体积平衡，XL1509 的典型推荐值** | —— |
| 100 µH | ≈ 0.20 A | 纹波更小 | 体积大、直流电阻大、瞬态响应变慢、成本高 |

**工作模式说明（重要）**：CCM（电流连续）与 DCM（电流断续）的边界是 `Iout > ΔI_L/2 = 210 mA`。本设计负载平均只有 58mA、峰值 131mA，**都小于 210mA，所以最高输入电压下变换器工作在 DCM**。

这**不影响输出稳压** —— XL1509 的 PWM 环路支持占空比 0%~100% 线性调节；而且 DCM 下的实际纹波比按 CCM 算出的 0.42A **更小**，所以上面这个 0.42A 是一个**安全的保守上界**，后面按它算电容是偏严的，符合工程习惯。

---

**③ 输出电容 330 µF + 4.7 µF 的确定**

输出纹波由**两部分叠加**，只看容值是不够的：

```
① 容性纹波（电容充放电）  ΔV_C   = ΔI_L / (8 × fsw × Cout)
② ESR 纹波（电容内阻压降）ΔV_ESR = ΔI_L × ESR
```

代入 ΔI_L = 0.42A、fsw = 150kHz：

```
① 330 µF 电解的容性纹波：
   ΔV_C = 0.42 / (8 × 150k × 330µ) = 0.42 / 396 ≈ 1.1 mV     → 可以忽略

② ESR 才是决定项：
   普通电解电容 ESR ≈ 0.1 Ω → ΔV_ESR = 0.42 × 0.1  ≈ 42 mV
   低 ESR 电解   ESR ≈ 50 mΩ → ΔV_ESR = 0.42 × 0.05 ≈ 21 mV
```

**这就是为什么必须并一颗 4.7 µF 陶瓷电容。** 注意一个容易误解的点：

```
4.7 µF 在 150 kHz 的容抗 Xc = 1/(2π × 150k × 4.7µ) ≈ 0.23 Ω
→ 比电解的 ESR 还大，所以它在 150kHz 上并不"分担"多少纹波电流

它的真正作用：ESR 只有几 mΩ，用来旁路**开关边沿的高频尖峰**
（远高于 150kHz 的分量，此时电解的等效串联电感 ESL 已呈感性、失去旁路能力）
```

**估算结果：3.3V 轨纹波约 20 ~ 40 mV（不到 1.3%），主要由电解电容的 ESR 决定。**

**另外，输出电容还要应对 LED 阵列的 250Hz 脉冲负载**：

```
负载在 96 mA 与 ~0 之间跳变（1ms 通 / 3ms 断）
开关电源环路带宽约 10 kHz → 响应时间约 100 µs
在这 100 µs 内由电容供给电荷：
   ΔQ = 96 mA × 100 µs = 9.6 µC
   ΔV = ΔQ / Cout = 9.6 µC / 330 µF ≈ 29 mV
   加上 ESR 压降 96 mA × 0.1 Ω ≈ 9.6 mV
→ 每次 LED 阵列开启时 3.3V 轨跌落约 30 ~ 40 mV，可以接受
```

> **对 ADC 的影响**：3.3V 同时是 ADC 的基准电压，所以上述 20~40mV 纹波会带来约 1% 的读数波动。本设计的两路 ADC 用途都不敏感 —— 电位器只映射到 19/21 个档位，电源键的判定阈值（1200mV）离实际电平（0V / 2.0~2.6V）余量极大，再加上固件里的一阶低通滤波，完全够用。

---

**④ 输入电容 470 µF + 100 nF 的确定**

**先看 RMS 纹波电流**（这是选输入电容的关键指标，超了会发热鼓包）：

```
I_Cin,rms = Iout × √(D·(1−D))

  Vin = 5 V （D=0.66）：131 mA × √(0.66×0.34) = 131 mA × 0.474 ≈ 62 mA
  Vin = 30 V（D=0.11）：131 mA × √(0.11×0.89) = 131 mA × 0.313 ≈ 41 mA
→ 最大 62 mA
```

常见 470µF/35V 电解电容的允许纹波电流在 **0.5 A 以上**，62mA 只有它的 12%，**余量 8 倍**，非常安全。

**再看容性纹波**：

```
ΔV_in = Iout × D × (1−D) / (fsw × Cin)
      = 0.131 × 0.66 × 0.34 / (150k × 470µ)
      = 0.0294 / 70.5 ≈ 0.4 mV          → 可以忽略
```

和输出侧同理，**实际输入纹波由 ESR 决定**：`ΔV ≈ Iout × ESR`。即使按 0.2Ω 的普通电解算，也只有 `131mA × 0.2Ω ≈ 26 mV`，相对 5V 输入仅 0.5%。

**100 nF 陶瓷电容的作用**：电解电容在 MHz 以上因 **ESL（等效串联电感）** 呈感性，失去旁路能力。100nF 专门负责旁路开关边沿的高频尖峰，抑制 EMI 和输入过冲 —— 对宽压输入（最高 30V）尤其重要，因为尖峰是叠加在 Vin 上的，会直接考验芯片的耐压余量。

**470 µF 的容值为什么比输出侧还大**：输入侧要同时承担三件事 ——
1. 在开关管导通期间为电感提供脉冲电流；
2. 吸收 LED 阵列脉冲负载经变换器反射到输入端的低频波动；
3. **配合较长的 USB 线缆电感**（线缆电感可达 µH 级，与输入电容构成 LC 谐振），容量越小越容易被线缆电感"顶"得电压跌落。

**耐压是这里最硬的一条约束**：最高输入 30V，电解电容**必须选 ≥50V 耐压**（按 1.6 倍以上降额），陶瓷电容选 ≥50V。铝电解的寿命随温度每升高 10℃ 减半，且**耐压余量不足会显著缩短寿命**，这一项不能省。

---

**⑤ 续流二极管 SS34 的确定**

SS34 是**肖特基二极管，额定 3A / 40V，SMB（DO-214AA）贴片封装**。

**电流校核**（二极管只在开关管关断期间导通）：

```
I_D,avg = Iout × (1 − D)
  Vin = 5 V ：58 mA × 0.34 ≈ 20 mA
  Vin = 30 V：58 mA × 0.89 ≈ 52 mA
峰值 = 电感峰值 ≈ 0.34 A
→ 相对 3A 额定值余量约 9 倍
```

**耐压校核**（二极管反向承受的电压就是 Vin 加上开关尖峰）：

```
最高输入 30 V，按 1.25 倍降额 → 需要 ≥ 37.5 V
SS34 的 40 V 满足，余量 10 V
```

**为什么必须用肖特基**：

```
正向压降 Vf ≈ 0.3 ~ 0.45 V   （普通硅整流管约 0.7 ~ 1 V）
续流损耗 = Vf × I_D,avg = 0.35 V × 52 mA ≈ 18 mW      → 几乎不发热

反向恢复时间极短（肖特基无少数载流子存储效应）
→ 开关损耗和 EMI 都明显小于普通二极管
```

> ⚠️ **耐压余量提醒**：SS34 的 40V 相对 30V 上限只有 33% 余量。如果实际使用中输入端可能出现**热插拔、长线缆振铃或感性负载反冲**导致超过 30V 的瞬态，建议换成 **SS36（60V/3A）**，成本几乎一样，余量翻倍。这是本电源里唯一值得再确认的一处降额。

---

**⑥ 损耗与效率核算**

**30V 输入时**（最恶劣，也是为什么必须用开关电源的原因）：

| 损耗项 | 计算 | 功耗 |
|---|---|---|
| 输出功率（有用） | 3.3 V × 58 mA | 190 mW |
| XL1509 自身工作电流 | 2 mA × 30 V | 60 mW |
| 续流二极管 | 0.35 V × 52 mA | 18 mW |
| 开关管导通 + 开关损耗 | Rds(on) 与 Qg 都很小 | ≈ 20 mW |
| **输入功率合计** | | **≈ 288 mW** |

```
效率 ≈ 190 / 288 ≈ 66%
```

**5V 输入时**：

```
输出 190 mW + 芯片 10 mW + 二极管 7 mW + 开关 20 mW ≈ 227 mW
效率 ≈ 190 / 227 ≈ 84%
```

**对比 LDO 方案（同样 30V 输入、同样负载）**：

```
LDO 自耗 = (30 − 3.3) × 58 mA ≈ 1.5 W
输入功率 ≈ 1.5 W + 0.19 W = 1.69 W
效率 ≈ 190 / 1690 ≈ 11%
```

**结论：30V 输入下开关电源的效率是 LDO 的 6 倍（66% vs 11%）；换算成绝对量，输入功率只有它的 1/5.9（288mW vs 1690mW），而电源自身损耗只有它的 1/15（98mW vs 1500mW）。**

> 顺便说明：30V 输入、轻载时 XL1509 的**自身工作电流（2mA × 30V = 60mW）反而成了最大损耗项**，效率从 5V 时的 84% 掉到 66%。这是所有**非同步 Buck 在高压差轻载下的共同特点**，不是选型问题；相比之下 LDO 的 1.5W 仍然大 5 倍以上。

#### EN 使能引脚：一键开关机的基础

XL1509 带 **EN（Enable）引脚，支持 TTL 电平关断及迟滞**。这意味着：

- **EN 有效（使能）** → 芯片正常工作，输出 3.3V；
- **EN 无效（关断）** → 芯片进入**关断态**，内部振荡器与功率管停止工作，**自身静态电流降到几十 µA 量级**。

这正是“关机静态电流 <1mA”能轻松达成的关键：

| 方案 | 关机后电源芯片自身的电流 |
|---|---|
| LDO 方案 | 5mA 量级（**仅这一项就超标 5 倍**） |
| **XL1509 + EN 关断** | **几十 µA 量级** ✅ |

所以开关机电路不需要去切断输入电源通路（那样需要串一个大电流 PMOS，还带导通损耗和散热问题），**只要控制 EN 引脚即可** —— 电路更简单、静态电流更小、可靠性更高。

具体电路见 §5.1。

## 5. 进阶功能实现方案

### 5.1 一键开关机（要求：非自锁开关，关机静态电流 <1mA）

#### 设计思路：控制 EN 引脚，而不是切断电源通路

一开始的思路是“在电源通路上串一颗 PMOS 做自锁开关”。但改用 **XL1509 开关电源**之后，有了**更好也更简单**的方案：

XL1509 自带 **EN（Enable）使能引脚**，支持 TTL 电平关断：

| EN 引脚 | 芯片状态 | 自身电流 |
|---|---|---|
| 使能 | 正常工作，输出 3.3V | 约 2 mA（工作静态电流） |
| **关断** | 振荡器与功率管停止，输出关闭 | **几十 µA 量级** |

所以开关机电路**不需要串在电源通路上**（那样要选大电流 PMOS、还要承担导通损耗和散热），**只要控制 EN 引脚**即可：

- 关断时芯片本身只吃几十 µA → **“关机静态电流 <1mA”轻松达成**；
- 输入通路始终接着，没有大电流开关管，**电路更简单、更可靠**；
- EN 引脚带**迟滞**，抗干扰好，不会在阈值附近抖动。

#### 硬件原理

```
  Vin (5~30V) ──┬──────────────────────────────┐
                │                              │
               === Cin                    ┌────┴─────┐
                │                         │  XL1509  │
               GND                        │          │
                                          │  EN      │◀──┬── 电源键（非自锁，按下把 EN 拉向使能电平）
                                          └──────────┘   │
                                                         └── KEY1(PB11) ── 单片机拉高 → 保持 EN 有效（自锁）
```

- **按下电源键** → EN 变成有效电平 → XL1509 启动 → 3.3V 建立 → MCU 上电；
- **MCU 初始化** 把 **KEY1(PB11) 置高** → 经开关机电路**保持 EN 有效** → **松手后仍继续供电**（自锁）；
- **关机**：把 **KEY1 拉低** → EN 失效 → XL1509 停止输出 → 3.3V 塌陷 → 整机掉电。

> **待完善**：请按你的原理图补充 EN 引脚的具体驱动电路（上拉/下拉电阻阻值、是否用三极管做电平转换、按键如何接）。重点是说明**“松手后靠 KEY1 保持”**这条通路。

#### 按键状态识别（ADC 采样）

电源键同时还接到 ADC 采样点，用来判断“用户是不是又按了一下”：

| 按键状态 | ADC 读数 | 判定阈值 |
|---|---|---|
| **未按下** | ≈ **0 V**（按键把该点接地） | `< 1200 mV` → 松开 |
| **按下** | **2.0 ~ 2.6 V**（分压） | `≥ 1200 mV` → 按下 |

阈值取 **1200mV**：离“按下”最低的 2.0V 有 800mV 余量，离“松开”的 0V 有 1200mV 余量，抗干扰能力强。

#### 状态机

```
上电
 ↓
WAIT_RELEASE ──连续 30ms 读到低电平──▶ ARMED ──连续 150ms 读到高电平──▶ 关机时序
   │                                    ▲   │
   │                                    │   └──读到低─────┐（计数清零）
   └──5s 一直读到高──▶ DISABLED ────────┘                 │
                        读到低（松开）即重新武装 ──────────┘
```

**“按下上电不能立刻又关机”是本功能最容易踩的坑**，用两道保险解决：

1. **上电静默 300ms**：ADC 的 DMA 缓冲上电时初值为 0、第一次转换还要等 TIM3 的触发，所以最开始读到的必然是“假低电平”。不屏蔽掉的话，“连续 3 次低电平算松手”这条规则可能在上电瞬间就成立，误判成“已松手”→ 进入 ARMED → 紧接着读到真正的高电平 → 150ms 后**自己把自己关掉**。
2. **WAIT_RELEASE 状态（主保险）**：按一下上电时按键是**一直按着**的，MCU 跑起来那一刻 ADC 必然是高电平。**没有连续读到“松开”（回到 0V）之前，按多久都不会关机。**

**超时保护与它的可恢复性（踩过的坑，见 §6.18）**：若 5 秒后仍一直读到高电平（按键卡住 / ADC 未接线 / 引脚悬空），进入 `DISABLED` 并打印日志。

> ⚠️ **`DISABLED` 必须是可恢复的**：上电时按键本来就是按住的，而**开机自检动画要跑 5.84 秒** —— 用户按着电源键看动画就会超过 5 秒的超时。如果 `DISABLED` 是终态，这次上电就**再也关不掉机**（只能拔电）。所以固件在 `DISABLED` 下持续检测：**一旦读到按键松开就立刻重新武装（`DISABLED → ARMED`）**，超时保护退化为“只是晚一点武装”，不再有不可逆的后果。

#### 按键门槛为什么是 150ms

人正常轻触一下按钮常在 **100~250ms**，门槛设 300ms 会让不少“按一下”被当成误触直接取消 —— 表现就是“关不掉机”。取 **150ms**：仍能挡住抖动和手碰一下的误触，但正常按一下能可靠触发。

#### 关机是在**按住时**执行，电源真正断掉是在**松手时**

这一条容易被误解，写清楚：

```
按下电源键 ──满 150ms──▶ MCU 立即执行关机时序：
                          · 停定时器、灯全灭
                          · KEY1 拉低（松开自锁）
                          · 进死循环
                              ↓
                        但此时按键还按着，EN 仍被按键本身使能着
                              ↓
松手 ──────────────────▶ EN 失去使能 → XL1509 关断 → 整机掉电
```

**软件没有等松手** —— `KEY1` 是在按住的第 150ms 就拉低的。但**电源电压只有在松手那一刻才会塌陷**，因为按键本身也是使能 EN 的一条通路（`EN 有效 = 按键按下 OR KEY1 有效`，两条是并联的）。

这是“按一下上电”这类自锁电路的固有特性：按键必须能在 MCU 还没上电时独立使能电源，所以按住期间它必然压过 KEY1。**观感上就是“按住 → 灯灭 → 松手 → 断电”，符合直觉，不需要改。**

> 如果希望**按住不放就能立刻断电**（不等松手），那就不能让按键与 KEY1 在 EN 节点上并联 —— 常见做法是在按键的使能支路串一颗电容，让按键只提供一个“启动脉冲”，之后完全靠 KEY1 保持。这属于硬件改动，需要时再评估。

#### 关机时序（顺序不可颠倒）

```
1. 打印关机提示，等发送空闲（最多 30ms）确保日志发得出去
2. 停掉 TIM1 / TIM2 / TIM3      ← 必须最先做，否则中断会把 GPIO 改回去
3. 阴极全低 + 4 个 PMOS 全关    ← 灯全灭
4. KEY1 拉低                    ← 松开 KEY1 这条自锁通路
5. 停止 SysTick + 死循环 __WFI() ← CPU 歇下来，等 3.3V 轨塌下去
```

> 第 4 步之后，若按键仍被按住，EN 还会被按键本身使能着，**3.3V 要等松手才塌陷**（见上文）。此时 MCU 已经在死循环里、灯已全灭，不会有任何残留动作。

#### 关机静态电流 <1mA 的实现要点

| 措施 | 作用 |
|---|---|
| 停掉三个定时器与 SysTick | 消除动态功耗 |
| CPU 进入 `__WFI()` 睡眠 | 内核电流降到 µA 级 |
| 12 个 MOS 栅极置安全态 | 无栅极漏电、无 LED 微亮 |
| **KEY1 拉低 → XL1509 进入 EN 关断态** | **本指标的关键**：电源芯片自身从 2mA 降到**几十 µA 量级**（对比：LDO 方案仅这一项就有 5mA，直接超标 5 倍） |
| MCU 未用 IO 的处理 | 建议在 PCB 上把未用 IO 通过电阻接地或设为模拟输入（见 §4） |
| 输入端分压/上拉网络的电流 | 若 EN 网络或 ADC 采样网络直接从 **Vin（最高 30V）** 取分压，其电流在整个关机期间持续存在，需按 `Vin / R_total` 核算并取足够大的阻值（这是本方案唯一需要留意的静态电流来源） |

> **实测数据待填**：关机状态下整机静态电流实测值 ______ mA（建议分别在 5V 和 30V 输入下各测一次 —— 30V 时输入端分压网络的电流最大）。

### 5.2 可控亮度与速度（电位器 + ADC）

#### 采样链路

```
电位器分压 ──▶ PA1 (ADC_IN1) ──┐
电源键分压 ──▶ PA0 (ADC_IN0) ──┤
                              └──▶ ADC1 ──DMA（循环，2 通道）──▶ s_raw[2]
                                        ▲
                             TIM3 TRGO（100Hz Update 事件）触发转换
```

- **ADC 校准**：`HAL_ADCEx_Calibration_Start()` 必须在 `HAL_ADC_Start_DMA()` **之前**调用，否则偏差可达十几 mV；
- **循环 DMA**：两通道自动搬运，CPU 零参与；
- **软件滤波**：前 4 次直接取值（快速建立），之后一阶低通 `y = (3y + x) / 4`，抑制抖动。

> ⚠️ 这里有一个**踩过的坑**：CubeMX 默认把 TIM3 的 `MasterOutputTrigger` 配成 `TIM_TRGO_RESET`（即 UG 位软件更新），**不是周期性事件，ADC 因此从未被触发过**，表现为 ADC 读数恒为 0。必须改为 `TIM_TRGO_UPDATE`。详见 §6.1。

#### 电位器 → 参数映射

| 电位器位置 | 亮度峰值 `duty` | 速度 `g_speed`（tick/步） | 直观感受 |
|---|---|---|---|
| 0%（最左） | 4 级 | 50（500ms/步） | 很暗、很慢 |
| 50%（中间） | 约 8 级 | 12（120ms/步） | 中等 |
| 100%（最右） | 19 级（满档） | 2（20ms/步） | 最亮、最快 |

**亮度用平方律**：人眼对亮度的感觉近似是 `感知亮度 ∝ duty^0.33`，如果 duty 线性变化会“一亮就冲到顶、然后在上面磨蹭”。取平方后，感知亮度大致跟着电位器角度线性变化。

**亮度下限设为 4 级而不是 1 级**：1 级时每颗 LED 平均只有 **0.15mA**，亮房间里看着就是黑的，容易被误判成故障。4 级约 0.6mA，任何光线下都看得见。

**速度用等比表**（21 档）：让每转过一格，速度变化的**比例**差不多，手感均匀：

```
索引 = 百分比 / 5，值 = tick 数
50, 43, 36, 31, 26, 22, 19, 16, 14, 12, 10, 9, 7, 6, 5, 5, 4, 3, 3, 2, 2
```

#### KEY3 三档切换 + 软接管（本设计的核心交互逻辑）

`KEY3` 短按循环切换电位器控制的对象：

| 档位 | 电位器控制 | 另一个参数 |
|---|---|---|
| **③ 联动（默认）** | 亮度 **+** 速度 | —— |
| **① 亮度** | 只调亮度 | 速度**保持不动** |
| **② 速度** | 只调速度 | 亮度**保持不动** |

**软接管（soft takeover）**：这是解决“参数突然跳变”的关键机制。

- 有一个全局标志 `s_pot_linked`：**0 = 冻结**、**1 = 跟手**；
- **冻结的触发时机**（共 4 处）：上电时、切模式时、按 KEY3 换档时、从待机唤醒时；
- **解冻条件**：电位器相对“冻结时记录的位置”**转过 ≥ 5%**。5% 换算成实际量是 155mV ≈ 190 个 ADC 计数，远高于噪声，但要拧过一点点就能触发（约 1/20 圈）。

由此得到一组**不会跳变**的完整行为：

| 动作 | 结果 |
|---|---|
| 切 KEY3 档位 | 两个参数**都先冻住**；转电位器超过 5% 才开始跟手 |
| 切模式 | 同上（新模式从当前参数开始，不跳） |
| 开机动画 → MODE1 | 初值冻结在动画参数（19/19、120ms/点），**全程无跳变** |
| 手拧电位器超过 5% | 进入“手动调节中”，参数跟着旋钮走 |
| 蓝牙发指令 | 立即生效并冻结，直到用户再拧电位器 |

**为什么“未选中的参数要冻结，而不是回到默认值”**：假设在联动档把亮度调到很暗，然后想“只调速度”—— 如果此时亮度跳回默认的 15 级，屏幕会莫名其妙突然变亮。冻结则不会有这个现象。

### 5.3 呼吸灯（MODE3 / MODE4）

#### 包络设计：为什么用“半正弦”而不是“升余弦平方”

第一版用的是 **升余弦再取平方**（gamma≈2，从感知均匀性推导出来的形状）。实测发现**“快熄灭时亮度卡一下”**，分析后找到根因：

> 升余弦在两端本来就是平的（`u ≈ i²`，几乎不动），再平方就更平。而 `duty` 只有 20 级，底部一整段会被取整成 `duty = 0` —— 实测 **16 / 64 个相位（约 1 秒！）停在“全灭”**，然后一下子跳到 `duty = 1`（感知亮度 38%）。

改为**半正弦** `env[i] = 255 · sin(π·i/64)`：半正弦在 `i=0` 处**斜率最大、一点都不平**，每一个相位都在动，不会再有一大段浪费在 `duty = 0`。

| | 改之前（升余弦平方） | 改之后（半正弦） |
|---|---|---|
| 停在“全灭”的相位 | **16 / 64（约 1.0s）** | **1 / 64（0.06s）** |
| 相邻两级最大感知差 | **38%**（0→1 的突跳） | **10%**（1→2，60ms 内） |
| 一轮里的“死区” | 约 1 秒 | 无 |

实际 `duty = 半正弦[相位] × 亮度峰值`，所以电位器直接缩放整条包络。

#### “吸-停-呼-停”的对称停顿

第一轮只在下端加了熄灭停顿，结果**变亮明显比熄灭快**。原因是：

```
上升段（灭→全亮）  28 个相位槽 = 1.68s
下降段（全亮→灭）  28 个相位槽 = 1.68s      ← 本身完全对称
熄灭后停顿          6 个相位槽 = 0.36s      ← 只有下端有
```

眼睛判断“熄灭过程”时会把“灭着不动”那段**算进去**，于是熄灭 = 2.04s、变亮 = 1.68s，差 21%。改为**最高点也加对称停顿**后，两头都是 2.04s ✅

| | 只有下端停顿 | 两端对称停顿（当前） |
|---|---|---|
| 变亮总时长 | 1.68s | **2.04s** |
| 熄灭总时长 | **2.04s** | **2.04s** |

两个停顿时长都做成常量（当前各 3 个相位 ≈ 0.18s），调速时会跟着一起缩放。

#### 彻底熄灭

最低点 `duty` 设成 **0（真正断电）**。代价是 `duty 0↔1` 在感知上是 0↔38% 的跳变 —— 这是 **19 级 PWM 的物理极限**（LED 在 1/19 占空比时就已经挺亮了）。但 `duty=1` 时每颗 LED 平均只有 0.15mA，绝对亮度很低，加上最低点有停顿，实际观感就是“灯熄了、停一下、再亮起来”。

#### MODE4 的字母交接

`MODE4` 复用同一条包络，区别只在“谁亮”：只有**当前字母**的 8 个点权重满档。

**交接为什么自然**：换字母发生在**相位绕回 0**（此时 `duty = 0`，整屏全黑）的那一刻 —— 黑屏时换字母，看不到任何接缝。

### 5.4 模式切换

- **按键**：`KEY2`(PB14)、`KEY3`(PB15)，均启用内部上拉、按下为低；
- **去抖**：连续 3 个 10ms 节拍（30ms）稳定才认一次边沿，只在**按下沿**触发；
- **循环顺序**：`MODE1 → MODE2 → MODE3 → MODE4 → MODE5 → MODE1`；
- **模式号提示**：切换时**整屏快闪 n 下**（n = 模式号），因为板子上没有屏幕。一下闪灯 = 亮 100ms + 灭 70ms = 170ms，所以 MODE1 提示 0.17s、MODE5 提示 0.85s。

软件结构上，每个模式只实现 `init()` / `step()` 两个函数，由一张**模式表**驱动；KEY2 的循环顺序另用一张顺序表。**以后增加模式只需改这两处**。

### 5.5 【创新】开机自检动画

上电后自动跑一轮 `MODE5`（描边游走），结束后进入黑屏待机，等按键才开始演示。

- **自检价值**：32 个点逐个点亮一遍 —— 哪颗灯不亮、哪一路 MOSFET 虚焊、哪条阴极线断了，一眼定位；
- **参数固定**：走速固定 120ms/点、亮度固定满档，**完全不受电位器和 KEY3 影响**。自检必须每次都一样，而且一定要看得见（第一版因为跟电位器联动，在电位器位置偏低时慢了 2~4 倍且几乎不可见，等于自检失效）；
- **兼作开机动画**，让上电过程有观感。

### 5.6 【创新】串口遥测

USART1（PA9/PA10，**115200 8N1**）通过 **DMA** 发送，绝不在中断或主循环里阻塞等待：

```
[TLM ] MODE=3(BREATH) BRIGHT=13/19 SPEED=19 POT=BOTH PWR=ARMED ADC1=2mV ADC2=1650mV
```

- 电压一律用**整数 mV** —— 工程用 `nano.specs` 链接且未开 `_printf_float`，`printf("%f")` 会**静默输出空字符串**；
- 发送用单份静态缓冲 + 忙标志，带 **1s 看门狗**（忙标志卡死时强制解锁），连续失败 5 次主动 `HAL_UART_AbortTransmit()` 复位 HAL 状态；
- **10Hz 周期帧默认关闭**（否则手机蓝牙终端会被满屏滚淹没），用 `TLM1` 打开、`TLM0` 关闭；
- 另有若干**事件行**（`[MODE]` / `[M1 ]` / `[POT ]` / `[PWR ]` / `[BOOT]`）在状态变化时输出，便于调试；
- 多行输出走一个 **4 行发送队列**，每 10ms 发一行，避免被“发送忙”标志吃掉后面的行。

### 5.7 【创新】蓝牙 / 串口远程控制

手机通过蓝牙串口模块（接 PA9/PA10）发送文本指令，可远程改模式、亮度、速度并回读。

#### 指令集

| 指令 | 有效范围 | 作用 |
|---|---|---|
| `MODE<n>` | 1 ~ 5 | 切模式（复用 KEY2 那条路，会闪 n 下确认） |
| `BRIGHT<n>` | 0 ~ 100 | 亮度峰值百分比，走和电位器完全相同的平方律 |
| `SPEED<n>` | 0 ~ 100 | 速度百分比，走和电位器完全相同的等比表 |
| `ASK MODE` / `ASK BRIGHT` / `ASK SPEED` | —— | 回读当前值 |
| `TLM<0\|1>` | 0 / 1 | 关 / 开 10Hz 周期帧 |
| `HELP` 或 `?` | —— | 回读指令表 |

不区分大小写；结尾加 `\r`、`\n` 或**什么都不加**都能识别（依靠 IDLE 空闲线检测，或静默 200ms 自动成帧）。

#### 回包示例

```
[BOOT] BNGU_Light v1.0  Phase-F: BT serial control
[BT  ] OK MODE=3 (flashing 3 times)
[BT  ] OK BRIGHT=50% (7/19)  CTRL=HOLD  KEY3=BOTH
[BT  ] OK SPEED=30% (19)  CTRL=HOLD  KEY3=BOTH
[BT  ] BRIGHT=50% (7/19)  CTRL=POT  KEY3=BRIGHT
[BT  ] ERR MODE=9 out of range 1..5
[BT  ] ERR unknown 'FOO' | valid: MODE1-5 BRIGHT0-100 SPEED0-100 TLM0/1 ASK HELP
```

`CTRL` 字段的含义：

| 值 | 含义 |
|---|---|
| `CTRL=HOLD` | 参数**已冻结**，蓝牙设的值正在保持，电位器不会覆盖它 |
| `CTRL=POT` | **电位器正在手动调节中**，每 10ms 覆盖一次这两个参数 |

`KEY3=` 字段说明当前电位器只管哪个参数（`BOTH` / `BRIGHT` / `SPEED`），避免“CTRL=POT 但只有一个参数在动”的歧义。

#### 为什么不需要 RX DMA，也不用改中断优先级

- **接收机制**：用 `HAL_UARTEx_ReceiveToIdle_IT()`（接收直到空闲）。两个好处：HAL 内部自动续接收，不像逐字节 `Receive_IT` 那样要应用层反复重新武装；**自带 IDLE 空闲线检测**，天然给出帧结束。
- **CPU 代价**：115200 下字节率 11520/s，每字节一次中断约 4µs，连续满速收也只占 **4.6% CPU**（比 10Hz 遥测的 DMA 还低）。一条 `MODE3` 指令约 8 次中断 ≈ 32µs。
- **中断优先级完全不用改**：`USART1_IRQn` 本来就是**抢占优先级 3**（全系统最低）：

  | 中断 | 抢占 | 作用 |
  |---|---|---|
  | TIM1_UP / TIM2 | 0 | 扫描（槽切换 + 20kHz PWM） |
  | TIM3 | 1 | 100Hz 应用节拍 |
  | DMA1_Ch1 / Ch4 | 2 | ADC / 串口发送 |
  | **USART1** | **3** | 串口收发 |
  | SysTick | 15 | HAL 时基 |

  这意味着接收中断**只被扫描中断打断、绝不打断扫描** → 不会造成槽错位、亮度抖动或残影。最坏延迟 = TIM1+TIM2+TIM3+DMA ≈ 13µs，而 115200 下一个字节是 87µs，余量 6.7 倍 ✅
- **CubeMX 完全未改动**。

#### 软接管与蓝牙的配合

蓝牙改完参数后**立刻调用 `pot_freeze()`**（复用 §5.2 的软接管机制）。

这一步是**必须的**：`effects_tick()` 每 10ms 调一次 `pot_update()`，不冻结的话蓝牙刚设的值 **10ms 后就被 ADC 读数覆盖掉了**，表现就是“发了没反应”。冻结之后，蓝牙的值稳定生效，直到用户真的转动电位器（超过 5%）才把控制权交回旋钮。

## 6. 遇到的问题及解决方法

### 6.1 ADC 读数恒为 0 —— TIM3 的 TRGO 配错

| | |
|---|---|
| **现象** | 电位器怎么转，遥测里的 `ADC2` 都是 0mV；电源键也永远检测不到 |
| **定位** | 逐项核对 CubeMX 配置，发现 TIM3 的 `MasterOutputTrigger` 是 **`TIM_TRGO_RESET`** |
| **原因** | `TIM_TRGO_RESET` 输出的是 **UG 位（软件更新事件）**，只在软件写 UG 时产生一次，**不是周期性事件**。而 ADC 配的是外部触发，需要每个周期来一个触发脉冲 → 实际上从来没触发过 |
| **解决** | 改为 **`TIM_TRGO_UPDATE`**（每 10ms 的更新事件触发一次 ADC） |
| **教训** | 用外设做“定时触发源”时，必须确认 TRGO 选的是**周期性事件**而不是软件事件 |

### 6.2 三个定时器共用一个回调，不判断 Instance → 亮度乱跳

| | |
|---|---|
| **现象** | 屏幕亮度乱跳、字符位置错乱、有残影 |
| **原因** | STM32 HAL 的 `HAL_TIM_PeriodElapsedCallback()` 是**三个定时器共用的弱函数**。一开始没判断 `htim->Instance`，导致 TIM1（1kHz）和 TIM3（100Hz）的中断也去执行阴极 PWM 代码 —— 槽切换被打乱 |
| **解决** | 回调里**先按 `htim->Instance` 分派**，再调用各自的处理函数 |
| **教训** | 共用回调必须分派，这是最容易埋的坑之一 |

### 6.3 单个字符内 8 个点只能同亮度

| | |
|---|---|
| **现象** | 想做彗尾和渐亮，但同一个字符里 8 颗灯亮度完全一样 |
| **原因** | 软件 PWM 做在**共用的阴极线**上，一个 1ms 槽内只有一个字符导通，所以该字符的 8 个点共享同一个占空比 |
| **解决** | **槽内子时段加权**：把 1ms 槽再切成 8 个子时段，权重为 *w* 的点只在前 *w* 个子时段点亮。于是同一个字符内也能有 8 级明暗，且**不需要额外引脚、不需要驱动芯片** |
| **代价** | 8 个点的掩码预计算成 `g_submask[4][8]`（40 字节 RAM），中断里一次查表 |

### 6.4 快速切槽时的残影（鬼影）

| | |
|---|---|
| **现象** | 切换字符时，前一个字符的余光会漏到下一个字符上 |
| **原因** | PMOS 的栅极电容使其**关断需要时间**；槽切换瞬间，上一行的 PMOS 还没完全关断，阴极已经开始导通 |
| **解决** | 每个槽开始的 **1 个 tick（50µs）作为消隐期**：先把 8 条阴极全部拉低、同时打开新槽的 PMOS，50µs 后再开始正常 PWM。50µs 远大于 PMOS 的关断时间 |
| **代价** | 亮度上限从 20 tick 降到 19 tick（损失 5%），可接受 |

### 6.5 开机自检动画跟着电位器跑，慢到几乎看不见

| | |
|---|---|
| **现象** | 上电后自检动画要么慢得离谱、要么几乎全黑，等于自检失效 |
| **原因** | 动画复用了 MODE5，而 MODE5 的走速和亮度都跟电位器联动（默认联动档）。电位器位置偏低时，走速只有设计值的 1/2.2 ~ 1/4.2，亮度也被压到接近最低档 |
| **解决** | **把“开机动画”和“手动 MODE5”彻底解耦**：开机动画走速固定 120ms/点、亮度固定满档，完全不受电位器和 KEY3 影响；只有手动用 KEY2 选到 MODE5 时才跟电位器 |
| **教训** | 自检/开机提示这类“必须每次都一样”的流程，绝不能依赖可变的用户输入 |

### 6.6 开机动画结束后要按键才动，其实是“看不见”而不是“没切换”

| | |
|---|---|
| **现象** | 以为“动画跑完要按一下键才进 MODE1” |
| **原因** | 亮度被电位器压到 `duty = 1`（几乎全黑），而且 MODE1 开局是空屏，所以分不清“没切换”和“切换了但看不见” |
| **解决** | ① 把开机动画与电位器解耦（见 6.5）；② 亮度下限抬到 4 级；③ MODE1 开局立刻渲染第 1 个点；④ 明确把“跑完 → 黑屏待机 → 按任意键开始”做成设计，并打印日志 `animation done - standby` |
| **教训** | “看起来没反应”往往不是逻辑错，而是**输出幅度低到看不见**。关键状态变化一定要有日志 |

### 6.7 呼吸灯“快熄灭时卡一下”

见 §5.3 的详细分析。根因是**升余弦平方包络在底部的平坦段被取整成 `duty=0`**，16/64 个相位（约 1 秒）停在全灭后突跳。解决：换成**半正弦包络**（两端斜率最大，无浪费相位）。

### 6.8 呼吸灯不能彻底熄灭

| | |
|---|---|
| **现象** | 暗室里能看到最低点还有微光 |
| **原因** | 为了避免 `duty 0↔1` 的感知突跳，之前把最低档设成了 **1**，即每个 1ms 槽阴极仍导通 1 个 tick（50µs），每颗 LED 平均 0.15mA |
| **解决** | 最低档改为 **0**（真正断电）。同时在代码里明确记录取舍：`duty 0↔1` 的 38% 感知跳变是 **19 级 PWM 的物理极限**，只能靠提高 PWM 分辨率（TIM2 由 20kHz 提到 40kHz，19 级→38 级）进一步改善 |

### 6.9 变亮比熄灭快

见 §5.3。根因是**只在最低点加了停顿**，眼睛把“灭着不动”算进了熄灭过程。解决：最高点加**对称停顿**，改成“吸-停-呼-停”的节奏。

### 6.10 蓝牙设的值 10ms 后就被电位器覆盖

| | |
|---|---|
| **现象** | 手机发 `BRIGHT50`，回包 `OK`，但屏幕没变化 |
| **原因** | `effects_tick()` 每 10ms 调一次 `pot_update()`，软接管一旦处于“跟手”状态，就用 ADC 读数**覆盖** `g_bright`/`g_speed`。所以蓝牙设的值 10ms 后就没了 |
| **解决** | 蓝牙改完参数后**立刻调用现成的 `pot_freeze()`**（Phase 2 为 KEY3 换档做的软接管）。值先冻住，等用户真的转动电位器超过 5% 才重新跟手 |
| **附带收益** | 和“按 KEY3 换档”“切模式”的行为完全一致，用户不会觉得有两套逻辑在打架 |

### 6.11 开机 4 行提示只出来 1 行

| | |
|---|---|
| **现象** | 上电只看到第一行开机横幅，后面的指令提示全没了 |
| **原因** | 发送函数是“**发送忙就丢弃**”：DMA 发第一行要 5~7ms，紧接着调用的第二行必然撞上忙标志被丢掉，第三、四行同理 |
| **解决** | 加一个 **4 行发送队列** + `telemetry_pump()`，每 10ms 发一行。同时把 `telemetry_line()` 改成“忙时排队而不是丢弃”，既不会丢消息，也不会出现“后发生的行插到开机横幅前面”这种乱序 |

### 6.12 10Hz 遥测把手机蓝牙终端刷爆

约 850 字节/秒的 `[TLM ]` 满屏滚动，指令回包全被淹没。**解决**：10Hz 周期帧**默认关闭**，用 `TLM0`/`TLM1` 切换。调试时开、演示时关。

### 6.13 待机时蓝牙指令把屏幕点亮却再也切不过去

| | |
|---|---|
| **现象** | 黑屏待机时发 `BRIGHT50` 或 `MODE3`，屏幕被点亮，但**卡在亮着的画面**不动 |
| **原因** | 待机分支里 `effects_tick()` 直接 `return`，`flash_tick()`（负责闪灯提示和真正切模式）**根本跑不到**。而 `MODE` 指令走的是 `effects_request_mode()`，它设置好闪灯状态就返回了，没人推进它 |
| **解决** | 新增 `effects_wake()`：待机时收到任何串口设置指令，先唤醒进 MODE1 再执行；`effects_request_mode()` 里也单独处理待机情形（跳过“已经是当前模式就返回”的判断） |

### 6.14 `printf("%f")` 静默输出空字符串

| | |
|---|---|
| **现象** | 想打印电压浮点值，串口上却是空的 |
| **原因** | 工程用 `nano.specs` 链接且未开 `_printf_float`，浮点格式化被裁掉了 —— **不报错，只是输出空串** |
| **解决** | 遥测里电压一律用**整数 mV**（`%umV`），全部换算在 ADC 层完成 |
| **教训** | 嵌入式里“能编译、能运行、但输出不对”的问题，往往出在链接期裁剪而不是代码本身 |

### 6.15 关于“非扫描时 4 颗 LED 共用一个限流电阻”的澄清

最初分析时曾写过一个**错误结论**：“4 颗 LED 共用一个 100Ω 时总功耗 215mW，超过 0805 的 125mW”。核对后修正：

- 4 颗并联时**电阻上的压降是共享的**，总电流仍受电压预算约束 —— 约 11.7mA **总量**，而不是 4 × 11.7mA；
- 因此电阻功耗约 `11.7mA² × 100Ω ≈ 13.7mW`，**远低于 125mW**；
- 真正的问题是 **Vf 不一致导致的分流不均**（可达 2:1 ~ 3:1），表现为“有的亮有的暗”；
- 本固件**始终扫描**（任意时刻只开一行），每颗点亮的 LED 独占本列电阻，所以这个状态不会出现。

**教训**：并联 LED 共用一个限流电阻时，要区分“**总电流受限**”和“**分流不均**”两个不同的问题，不能混为一谈。

### 6.16 中断优先级分层设计

扫描中断（TIM1/TIM2）与串口中断如果优先级配置不当，会出现“串口收数据时屏幕闪一下”之类的现象。

**解决**：把优先级按“**谁绝对不能被延迟**”分层：

| 优先级 | 中断 | 理由 |
|---|---|---|
| **0** | TIM1_UP、TIM2 | 扫描时序。两者**故意设为同一级** → 互不抢占 → 两次 GPIO 写（GPIOA + GPIOB 的 BSRR）成为**原子操作**，不会出现“阳极开了阴极还没换”的瞬态 |
| 1 | TIM3 | 应用节拍 + ADC 触发，可被扫描打断 |
| 2 | DMA1_Ch1/Ch4 | 数据搬运，可稍等 |
| **3** | USART1 | 串口收发，**全系统最低**，只被扫描打断、绝不打断扫描 |
| 15 | SysTick | HAL 时基，谁都能打断它 |

这样**任何通信行为都不可能干扰 LED 扫描的时序**。

### 6.17 30V 输入下 LDO 方案根本走不通

| | |
|---|---|
| **现象** | 按“USB 5V 输入 + LDO 转 3.3V”的常规思路做，在题目要求的宽压（最高 30V）下无法成立 |
| **计算** | LDO 是线性稳压，输入多余电压全部变成热。整机 3.3V 轨平均约 58mA：<br>`P_LDO = (30 − 3.3) × 0.058 ≈ 1.5 W`<br>常见 SOT-223 封装 LDO 的热阻约 60~100℃/W，1.5W 会让结温升高 **90~150℃**，直接过热保护或烧毁；加再大的散热铜皮也压不住 |
| **本质原因** | LDO 的效率 ≈ `Vout / Vin`。5V 输入时还有 66%，30V 输入时只剩 **11%**，89% 的能量变成热 |
| **解决** | 改用**开关电源 XL1509**（降压型 DC-DC，4.5~40V 输入）。它是靠电感储能+开关斩波变换，效率约 80~90%，**与输入电压基本无关**，30V 输入时自身损耗只有 0.2W 以内 |
| **连带收益** | ① 顺带实现题目选做项“宽压输入”；② XL1509 带 **EN 使能引脚**，一键开关机只要控制 EN 即可，**关机时芯片自身电流从 2mA 降到几十 µA**，“关机静态电流 <1mA”迎刃而解（若用 LDO，仅它自己的 5mA 静态电流就已经超标 5 倍） |
| **连带代价** | ① Buck 只能降压不能升压，且有 1.5V 最小压差 → **输入下限只能是 4.8V，题目要求的 4V 无法达到**，最终定 5V（见 §3.5）；② 需要额外的电感、续流二极管、输出电容，且**布局对开关噪声敏感**（见 §4） |
| **教训** | **宽压输入和线性稳压本质上是矛盾的**。看到“输入 4~30V、输出 3.3V、还要低静态电流”这组需求，就应该第一时间想到开关电源，而不是先画 LDO 再想办法散热 |

### 6.18 一键开关机“关不掉机”—— 超时状态不可恢复 + 门槛过长

| | |
|---|---|
| **现象** | 长按/短按电源键都无法关机，只能拔电 |
| **定位过程** | 先排除了两个方向：① **软件没有等松手** —— `do_shutdown()` 是在按住的第 N 个节拍就执行的，`KEY1` 当场拉低；② **ADC 通道没错** —— `.ioc` 里 `ADC_CHANNEL_0`(PA0 电源键) 是 Rank 1，对应 DMA 缓冲 `[0]`，与固件假设一致 |
| **真正原因 1（主因）** | **`DISABLED` 状态是终态**。上电后的按键逻辑是：连续 5 秒读到高电平就判定“按键卡住”并永久放弃关机检测。但**上电时按键本来就是按住的**，而**开机自检动画要跑 5.84 秒** —— 只要按着电源键把动画看完，就必然超过 5 秒 → 进入 `DISABLED` → **这次上电再也关不掉机**。设计时只考虑了“按键卡死保护”，完全没想到“正常按住也会触发”，而且触发后不可逆 |
| **真正原因 2（次因）** | **关机门槛 300ms 比人的“按一下”更长**。正常轻触按钮常在 100~250ms，未达门槛就计数清零，表现同样是“关不掉机” |
| **解决** | ① **让 `DISABLED` 可恢复**：在该状态下持续检测，读到按键松开就立刻回到 `ARMED`，超时保护退化为“只是晚一点武装”，不再有不可逆后果；② 门槛从 300ms 降到 **150ms**，既能挡住误触，又能让正常“按一下”可靠触发；③ 在按下沿和取消时各打一行日志（含实际读到的 mV），下次一眼就能看出是“ADC 没读到”还是“状态机没走对” |
| **附带澄清** | 用户怀疑“固件是不是等松手才拉低 KEY1”—— **不是**。`KEY1` 在按住的第 150ms 就拉低了；但**电源电压要等松手才塌陷**，因为按键与 KEY1 在 EN 节点上是**并联**的（`EN 有效 = 按键按下 OR KEY1 有效`）。这是“按一下上电”电路的固有特性：按键必须能在 MCU 上电前独立使能电源，所以按住期间它必然压过 KEY1 |
| **教训** | ① **超时/保护类的状态机，任何“终态”都要问一句“用户怎么出来”** —— 不可恢复的降级状态是嵌入式里最隐蔽的坑；② **给用户的提示必须写成“操作契约”**（按住多久、按几下），并且门槛要按人的真实操作时长来定，不能凭感觉；③ 关键动作上加一行带**实际采样值**的日志，排查成本能从几小时降到几分钟 |
